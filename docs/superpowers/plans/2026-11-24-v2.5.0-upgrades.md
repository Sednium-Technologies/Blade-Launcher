# Blade Launcher v2.5.0 Upgrades Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement In-App OTA Update Modal, Android Notification System (Process Running + Terminate, OTA Alert, Background Download Progress), Portrait Task Menu Drawer overflow fix, and Portrait Controls Settings layout adaptation, bumping to version 2.5.0.

**Architecture:** 
1. `BladeNotificationManager` centralizes Android 13+ `POST_NOTIFICATIONS` channels (`channel_game_running`, `channel_ota_updates`, `channel_download_progress`). `GameService` displays an ongoing notification with inline `PendingIntent` that cleanly terminates the `:game` process.
2. In-App OTA Updater downloads GitHub release `.apk` matching device architecture into `context.cacheDir/ota/` with live progress, speed, and cancel; installs directly via `FileProvider` and `ACTION_VIEW` (`REQUEST_INSTALL_PACKAGES`).
3. Compose UI responsive adaptations for `ORIENTATION_PORTRAIT` in `MainScreen.kt` (Task Menu 88% width) and `ControlManageScreen.kt` (vertical stacked 2-pane layout, full-width details, and equal 50% Share/Edit action buttons).

**Tech Stack:** Kotlin, Jetpack Compose, AndroidX NotificationCompat, FileProvider, OkHttp/Coroutines, Android Gradle Plugin, ProGuard/R8.

## Global Constraints
- Match Sednium Warm Stone Light / `#EA580C` burnt-orange UI aesthetic.
- Preserve all ProGuard/R8 `-keep` rules and keep release minify working without reflection stripping.
- Support Android 8.0 through Android 14+ (API 26–34+).
- Use `bwrap` container for hermetic NDK builds to prevent path-space issues.
